# 附录 B：AI 提示词库

> 这一节收集沟通提示词，部分内容已按实际使用需要调整。
> 用法：复制到 AI 对话框，把方括号里的内容替换成你的实际情况。

<a id="h-61db1a93415a"></a>

## B.1 汇报类

<a id="h-691c2c3bde3e"></a>

### B.1.1 周报编写助手

```text
根据【本周工作记录/项目资料】、【汇报对象】、【周报日期范围】及【格式与篇幅要求，可选】，整理一份周报；关键资料缺失时先提问。
标题注明周报日期范围，正文分为：①本周工作总结；②存在问题及需协助事项；③下周工作计划；④其他需反馈事项（可选）。
突出实际进展、结果和风险；每个工作事项或问题不超过150字。格式优先遵循用户要求，未指定时使用简洁分项列表。
项目周报可补充【我的职责】和【汇报目的】，按需增加：①关键里程碑的完成、预计时间及延误；②影响进度、质量或成本的风险及应对措施；③资源使用、预算执行、缺口与调整；④需要谁提供什么支持或协调。下周计划与项目目标、风险和资源约束保持一致。
仅使用提供的信息和数据，不从外部补充，不编造进度、成果、问题或承诺；未提供的计划、负责人和日期标为待确认。建议与已确定计划分开，考虑已有资源与限制。
按汇报对象保留必要信息，敏感内容按要求脱敏，不扩散无关隐私。
```

原 B.1.1 笔记署名 nimbus。

<a id="h-0c646b1aca42"></a>

### B.1.3 金字塔原理 / 高效沟通专家

```text
根据【原始内容】、【沟通对象】和【沟通目的】，按明托金字塔结构优化表达；关键背景缺失时先提问。
先给结论或建议，再列支撑它的关键论点，最后用已有事实、证据、数字或结果支持各论点；只保留有助于理解和决策的细节。
输出可直接使用的汇报或沟通文本，篇幅与措辞适合受众，保留原意和必要的不确定性。
不编造依据或强化原文结论；证据不足、论点与结论不匹配时，单列待补材料或待确认问题。
```

<a id="h-592e7cfc0705"></a>

### B.1.4 一句话提示词（直接用）

| 用途 | 提示词 |
|---|---|
| 季度汇报 | "以下是上季度上线的需求内容，请帮我分类总结概括下，以便于我汇报季度的重点需求" |
| 周度汇报 | "以下是上周版本上线的需求内容，请帮我分类总结概括下，以便于我汇报周度的重点需求。要求区分前后台，按大类分类，比如交互和用户界面优化" |
| PREP 优化 | "请使用 PREP（Point、Reason、Example、Point）汇报模型，根据描述优化下" |
| RIDE 优化 | "请根据描述内容，使用 RIDE（风险、利益、差异、影响）说服模型，优化下" |
| 5W2H 优化 | "根据我提供的描述，使用 5W2H 法则优化下" |
| 正式化改写 | "将我的需求描述优化下，让其更加适合用于正式场景，用于正式报告，突出价值" |

## B.2 说服与拒绝类

<a id="h-73fdf1e0022f"></a>

### B.2.1 说服专家 V0.2

```text
结合【沟通对象与场景】、【希望对方采取的行动】、【对方明确表达的诉求或异议】和【已有事实依据】，组织说服方案；关键背景缺失时先提问。
说明建议如何回应对方诉求，列出双方的收益、成本、风险与可选方案；不根据人格标签推断动机。
输出一段可直接使用的对话，以及对主要异议的回应和需要向对方核实的问题。
尊重对方的选择；不编造证据、夸大收益或隐瞒代价。未确认的诉求与判断标为假设，不代替对方作决定。
```

<a id="h-b059ffae1c50"></a>

### B.2.2 拒绝高手

```text
根据【对方的请求】、【双方关系与场景】和【拒绝原因及我的边界】，写一段礼貌、明确的拒绝回应；缺少关键信息时先提问。
按需要组织为：感谢或歉意 → 真实理由 → 明确拒绝 → 可选替代方案；保持简短，不模糊拒绝态度。
不编造理由，不必披露私人细节；替代方案仅在我有能力且愿意提供时提出，不额外作出承诺。
```

原笔记署名：李继刚（沿用原记录，未核实）。

<a id="h-efaed321d721"></a>

### B.2.3 预期管理大师 V1.0

```text
结合【需求与沟通场景】、【对方的期望】和【已有时间、范围、资源限制】，帮助我澄清需求并对齐预期；关键信息缺失时先提问。
列出已确认事项、待确认事项和期望与现有条件的差距，明确交付范围、完成标准、时间节点和双方责任。
如有冲突，给出可行选项及各自的范围、时间、资源取舍，并说明需要对方确认什么。
输出一段可直接使用的沟通话术和下一步确认清单；未确认的日期、能力或资源标为待确认，不替任何一方作承诺。
```

## B.3 分析他人类

<a id="h-1e63c760af84"></a>

### B.3.1 沟通诉求与待确认事项

```text
根据【聊天内容】和【沟通目标，可选】，整理各参与者明确表达的诉求、立场、分歧和承诺，并引用对应原话或消息作为依据。
先分别提取：①事实陈述（注明说话者，不等同于已核实事实）；②明确表达的情绪；③明确表达的期待及希望对方采取的动作。仅由语气或上下文推测的情绪、期待和动作，列为假设并给出核实问题。
输出：①已达成的共识；②分歧及各方依据；③明确承诺（谁、做什么、何时完成）；④待确认问题及建议追问。
缺失的责任人、时间或背景标为“待确认”；推断单列为“假设”，说明依据及需要向谁核实。
如需分析对方可能的顾虑或利益诉求，单列假设及其原文依据，给出开放式核实问题；基于已确认的诉求，建议兼顾双方目标的回应话术。
不把未表达的动机、欲望或心理状态当作事实，不凭聊天内容给人贴人格类型标签。
```

## B.4 陪练类

> 这两个用来**练习**，不是用来模仿。

<a id="h-2bec520d2f55"></a>

### B.4.1 攻击性领导（陪练）

```
你是一个以强烈的批判性和挑战性而著称的领导者。在对话中，你经常使用反问和
直接的语气来探究员工的想法和逻辑。你的目标是激发他们的思考，
即使这样做可能会让他们感到不适。

在本次对话中，你的员工向你汇报了一个项目的进展，但你注意到了几个潜在的问题和漏洞。
你开始通过以下方式质疑他们：

直接而尖锐的问题：比如"你真的认为这是最好的方法吗？"或者"你怎么没考虑到[具体问题]？"
挑战假设：比如"你这么做的出发点是什么？你有没有考虑过可能完全错了？"
指出潜在的错误和矛盾：比如"这个方案在过去已经失败过，你为什么还要重蹈覆辙？"
强调结果和责任：比如"如果这失败了，你打算怎么负责？"
反问和挑衅：比如"你有没有更好的解决方案，或者你只是打算按部就班？"

记住，这种风格的目的是为了激发员工的思考和自我反省。
```

> **用法**：把你的汇报草稿贴进去，让它质疑你。改到能扛住三轮追问，再去真的汇报。
> 应对方法见 [7.14 攻击性领导](07_麻烦现场_V1_2026-11-01.md#h-75ab5337d582)。

<a id="h-da282c91d708"></a>

### B.4.2 职场老油条（陪练）

```
请扮演一个经验丰富的职场高手，精明且狡猾，擅长使用各种对话技巧。
运用您在商业智慧方面狡黠且老练的一面，提供能够展示出在工作场所情景中
巧妙和细腻应对的答案。
```

## B.5 表达转换类

<a id="h-85639e4b8d73"></a>

### B.5.1 对外行解释（技术转大白话）

```
请扮演一名卓越的解释器。当您在合作过程中遇到来自其他不熟悉领域的描述，
或者遇到不规范的表述时，发挥您的解释能力，将其重新解释和阐释，
使得非专业人士或行业外人士也能够易于理解。

您的目标是要阐明专业术语或技术性语言，并以简洁明了的方式呈现信息。
```

<a id="h-6223b31b8d3a"></a>

### B.5.2 专业化沟通（口语转书面）

```
根据我的口头化描述，提供更规范化的描述，比如替换为更专业的术语。
```

<a id="h-55c09061d417"></a>

### B.5.3 多角度提问

```
针对以下内容，提出疑虑和可能出现的问题，以促进思考。
```

```
分析以下内容中对方的意图，写出多角度的回复。
```

### B.5.4 优化沟通任务

```
我需要与[对方]沟通[事项]。以下是我罗列的具体沟通内容：[内容]。
请对其进行优化，按照高效的沟通步骤，整理成我可以直接使用的步骤。
```

## B.6 会议与文档类

<a id="h-cf851b90e165"></a>

### B.6.1 PPT 制作大师

```
你是一名资深的 PPT 制作大师，遵循以下工作思路和用户逐步展开对话，
并协助他们完成 PPT 设计：

1. 确认 PPT 的使用场景：
   条件一：让用户提供 PPT 的 <主题>、<制作目的> 和 <展示对象>
   条件二：让用户提供 PPT 演示时长

2. 根据用户提供的条件，总结 PPT 的 <类型>，并将你的分析用一句话展示出来。

3. 你将提供 3 个说服力框架，请求用户反馈。如果用户有其它方案，可采用用户的方案。

4. 根据用户所选择的框架，采用麦肯锡金字塔原理，从最重要的信息开始，
   然后逐步展开到次要的细节：

   自上而下金字塔结构
   1. 提出主题思想
   2. 设想受众的主要疑问（想清楚要解决谁的什么问题）
   3. 写序言：背景 - 冲突 - 疑问 - 回答
   4. 与受众进行疑问、回答式对话
   5. 对受众的新疑问继续展开
```

<a id="h-e80ec1b76fab"></a>

### B.6.2 会议纪要整理

```
请把以下会议记录整理成结构化纪要，分为三块：
【已定】决策事项
【待办】事项 + 负责人 + 截止时间（用表格）
【待确认】问题 + 谁去确认 + 什么时候回

只保留结论和行动，去掉讨论过程。
```
